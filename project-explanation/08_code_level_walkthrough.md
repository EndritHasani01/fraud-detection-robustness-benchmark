# Code-Level Walkthrough

This file explains the implementation in the order the program executes. It is written for a technical reader who wants to understand the actual modules, not only the research idea. The most important pattern is that the repository separates experiment definition, graph materialization, model execution, result logging, and reporting.

Execution starts in `benchmark/run.py`. The `main()` function builds an `argparse` CLI with stages such as `graphs`, `baselines`, `pmp`, `secgfd`, `shift`, `matrix`, and `plots`. It loads the JSON config through `load_json()`, validates it through `validate_config()`, decides the output directory, parses requested model IDs, and dispatches to the stage function. It also prints a final stage status and elapsed time, and maps config errors to exit code `2`.

Config logic lives in `benchmark/config.py`. The `ExperimentPaths` dataclass defines standard output paths such as `config.json`, `results.csv`, `graph_variants.csv`, `variant_audit.csv`, and `graphs/`. The validation functions enforce known scenario methods, valid graph view modes, valid oracle metadata, valid seed lists, and valid SEC-GFD hyperparameters. Helper functions such as `get_graph_seeds()` preserve backward compatibility by falling back to training seeds when older configs do not define graph seeds.

The graph stage is `_graphs_only()` in `benchmark/run.py`. It initializes paths, writes a config copy, ensures the result CSV header exists, and creates temporary manifests for graph variants and audits. Temporary files are used so an interrupted graph stage does not leave a partially complete manifest pretending to be valid. At the end, the temporary files replace the final CSVs.

Inside the graph stage, `_make_source_graph()` loads DGL's `FraudDataset`, normalizes feature and label dtypes, and overwrites masks through `ensure_masks()`. Then `_to_canonical_graph()` converts the source graph into the configured canonical representation, usually homogeneous. The clean graph is saved with `save_graph()`, and `compute_graph_stats()` records the basic statistics used in ledgers and results.

For each scenario, severity, and graph seed, the graph stage builds a `ScenarioSpec`. If the scenario uses `heterograph_aware_generation`, the source heterograph is passed into `apply_scenario()`. If it uses `canonical`, the already converted base graph is passed in. If the scenario was applied and it came from the heterograph path, the result is converted back to the canonical graph before saving. This is the key v3 implementation detail that allows relation-aware generation and homogeneous evaluation.

Graph paths are created by `benchmark/paths.py`. `base_graph_path()` returns paths for the clean graph. `variant_graph_path()` returns paths for a variant based on dataset, split, scenario, severity, and graph seed. Graph saving is handled by `benchmark/cache.py`, which writes `meta.json` and a DGL `graph.bin`. No-op variants use `save_graph_ref()` so the variant folder can point to the base graph without duplicating the binary.

Scenario implementation is centralized in `benchmark/scenarios.py`. `apply_scenario()` rejects negative severity, returns a no-op for severity zero, creates a deterministic RNG, selects feature and label keys, builds an edge sampling policy, and dispatches by method string. After an applied change, it calls `_assert_invariants()` to verify that protected task data has not been changed.

Relation-aware graph operations are abstracted in `benchmark/relation_utils.py`. Functions such as `selected_relation_keys()`, `edges_by_relation()`, `rebuild_graph_with_edges()`, and `copy_node_data()` let scenario code work with either homogeneous graphs or heterographs. This helper module is why the scenario functions do not need to duplicate relation-selection logic.

Audit row construction is in `benchmark/scenario_audit.py`. `build_variant_audit_row()` takes base stats, variant stats, and scenario-specific `info`, then normalizes them into one wide CSV schema. It fills common requested and realized change fields, before/after graph stats, scenario-specific metrics, JSON-encoded relation breakdowns, and leftover extra info. This is what turns nested scenario logs into reportable tabular evidence.

The result schema is in `benchmark/results.py`. It defines `RESULTS_COLUMNS`, `VARIANTS_COLUMNS`, protocol constants, run-key helpers, CSV header migration helpers, and `write_result_row()`. The result-writing function builds common fields from a `VariantRow`, adds metrics or error status, and appends the row. The same function is used by all model stages, which is how the project maintains one unified result table.

Variant reading and filtering are in `benchmark/variants.py`. `read_variants_csv()` parses typed `VariantRow` objects from the graph ledger. `filter_variants()` applies common CLI filters such as `--include-noop`, `--only-clean`, and `--max-variants`. `set_seeds()` sets Python, NumPy, PyTorch, CUDA, and DGL seeds where available. This module gives training stages a common way to interpret the graph ledger.

Training preflight logic is in `benchmark/preflight.py`. It parses requested model IDs, selects configured models, builds expected run keys, loads completed keys, estimates remaining work from past median durations, and prints progress. The `ProgressTracker` prints per-run status lines with model ID, scenario, severity, graph seed, training seed, status, AUC, duration, and ETA. This is operational code, but it matters for long experiment runs.

Baseline model definitions are in `benchmark/baselines.py`, and baseline stage execution is in `benchmark/baselines_stage.py`. `train_baseline_model()` builds an MLP or GraphSAGE model, applies class-weighted cross entropy, monitors validation ROC-AUC, saves the best state, and computes the validation F1 threshold. `eval_baseline_model()` rebuilds the model from the artifact, evaluates test scores, and computes all metrics.

PMP execution is in `benchmark/pmp_stage.py`. The stage loads PMP YAML settings, merges benchmark overrides, creates `label_unk`, optionally normalizes features, builds DGL dataloaders, imports `LASAGE_S` from the research repo, trains with validation ROC-AUC early stopping, selects the validation threshold, and evaluates test metrics. It restores graph node data after temporary PMP-specific modifications so the same graph object is not left mutated for later runs.

SEC-GFD execution is in `benchmark/secgfd_stage.py`. The stage imports the SEC-GFD model class by file path to avoid package-name collisions, installs a theta coefficient cache, resolves hparams, trains with cross entropy plus the benchmark-fixed local constraint loss, monitors validation ROC-AUC, and evaluates the test split. It writes rows through the same result helper as every other model.

The clean-train shift path is in `benchmark/shift_stage.py`. It groups variants by dataset and split, finds the clean variant for each group, loads the clean graph, trains one artifact per model and training seed, and evaluates that artifact on every filtered variant. It writes the evaluation graph path in `graph_path` and the clean training graph in `train_graph_ref`. That column is how the result row tells you the model was not trained on the stressed graph.

The matrix launcher is in `benchmark/matrix_stage.py`. It first checks that the graph ledger exists, selects integrated model IDs, computes a preflight summary, and then dispatches. If the requested protocol is `train_clean_eval_all`, it calls `run_shift_stage()` and returns. Otherwise, it runs baseline, PMP, and SEC-GFD stages as needed. Only the first child stage receives `force=True`, which prevents later child stages from wiping earlier result rows.

Metrics are implemented in `benchmark/metrics.py` without requiring scikit-learn. ROC-AUC is computed with a rank-based Mann-Whitney formulation, average precision is computed from the sorted precision-at-positive positions, and macro-F1 is computed from binary confusion counts. `best_f1_macro_threshold()` searches unique validation score thresholds and uses deterministic tie behavior.

Plotting and reporting live in `benchmark/plots_stage.py`. The stage reads results and audit rows, indexes variants and audits by join key, checks audit completeness, computes missing and error run diagnostics, aggregates metric stats, optionally bootstraps confidence intervals, writes summary CSVs, and saves PNG plots. It also writes `performance_audit_join.csv`, which is the report-friendly bridge from model metrics to realized perturbation evidence.

The implementation is modular because each concern has a different stability requirement. Config validation must be strict. Graph generation must be deterministic and auditable. Model stages must be resumable. Results must have one schema. Plots must keep protocol and oracle labels visible. The modules mirror those requirements.
