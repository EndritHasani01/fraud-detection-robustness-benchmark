# Models And Training

The benchmark integrates four model IDs in the main configs: `mlp`, `sage`, `pmp`, and `secgfd`. The first two are implemented directly inside the benchmark package. The last two are imported from vendored research repositories and wrapped by benchmark adapter stages. The point of this model set is to compare simple baselines with specialized graph fraud detection methods under the same graph variants, splits, seeds, metrics, and result schema.

The `mlp` model is a feature-only baseline defined in `benchmark/baselines.py`. It is a multilayer perceptron with linear layers, ReLU activations, and dropout. It ignores graph edges completely. This model is not included because it is expected to be the best graph fraud detector. It is included because it answers an important sanity question: how much of the fraud signal is available from features alone, and do graph-only perturbations leave a feature-only model unchanged when they should?

The `sage` model is a GraphSAGE baseline defined in the same file. GraphSAGE is a message passing model. It computes node representations by aggregating neighbor information through DGL's `SAGEConv`. This makes it a useful contrast with the MLP. If graph structure becomes misleading or noisy, GraphSAGE may degrade because it actually uses the graph. That is exactly the kind of behavior the benchmark is designed to reveal.

Baseline training is implemented in `benchmark/baselines_stage.py`. The training function creates the model, moves tensors to the requested device when possible, builds class weights from the training labels, and optimizes cross-entropy loss. It monitors validation ROC-AUC for early stopping and stores the best model state. After training, it chooses the F1 threshold on validation scores and then evaluates ROC-AUC, average precision, and macro-F1 on the test split.

Class weighting is used because fraud detection is imbalanced. If the positive class is rare, a model can optimize loss by focusing too heavily on the normal class. The helper `class_weights_from_train_labels()` computes a positive-class weight based on the ratio of negative to positive training examples. This is a practical correction, not a complete solution to imbalance, but it keeps the baselines from being trivially dominated by the majority class.

PMP is integrated through `benchmark/pmp_stage.py` and the vendored repository `Repos/PMP-master`. PMP stands for Partitioning Message Passing. Its research motivation is that fraud graphs combine label imbalance with a mixture of homophilic and heterophilic neighborhoods. The model separates neighbor information by known or unknown training labels through a `label_unk` encoding and uses different transformations for different neighbor groups. In the benchmark, PMP is represented by LA-SAGE-S from the research repo.

The PMP adapter has to translate benchmark graphs into the assumptions expected by the research implementation. It creates `label_unk`, where train nodes keep their known labels and all other nodes are assigned an unknown value. It optionally row-normalizes features according to the PMP config. It builds DGL dataloaders with either full-neighbor or sampled-neighbor sampling. On Windows, it forces `num_workers = 0` for DGL dataloader stability. It then trains the imported model and evaluates it with the same benchmark metrics.

The PMP configuration is resolved by reading the original YAML file from `Repos/PMP-master/config/<dataset>.yml` and merging benchmark-side overrides from the JSON config. This is important because the benchmark wants to preserve the research model's structure while reducing runtime cost for a course benchmark. For example, the v3 config uses sampled neighbors, batch size 512, 100 epochs, patience 10, and `num_workers = 0`.

SEC-GFD is integrated through `benchmark/secgfd_stage.py` and `Repos/SEC-GFD-main`. SEC-GFD is a graph fraud detection model motivated by heterophily and graph spectrum. Its model combines band-pass style spectral filters with high-order components and a local environmental constraint. In the benchmark adapter, the imported `SECGFD` class is trained with cross-entropy plus a contrastive-like loss term controlled by `lemda`.

The SEC-GFD adapter resolves hyperparameters from the config and CLI overrides. The default benchmark-side values include hidden dimension 32, polynomial order `order_d = 2`, high-order depth 1, `lemda = 0.2`, learning rate 0.01, and weight decay 0.0. The stage supports runtime overrides such as `--secgfd-hid-dim`, `--secgfd-order-d`, and `--secgfd-high-order` so expensive settings can be adjusted without editing frozen configs.

The SEC-GFD integration includes two important benchmark-side adaptations. First, it caches the spectral theta coefficients computed by the research code so repeated runs do not recompute the same polynomial coefficients unnecessarily. Second, it fixes the contrastive-like loss indexing so it uses global node indices from the training split. These details are implementation-level, but they matter because they make the research model behave consistently inside the benchmark harness.

All model stages write results through `benchmark/results.py`. This keeps a single schema for every model. Whether the row came from MLP, GraphSAGE, PMP, or SEC-GFD, it includes the same identifiers, metrics, graph stats, graph paths, protocol, status, error, and duration. This is why the plotting stage can be model-agnostic. It does not need to know how PMP or SEC-GFD trained. It only needs the unified results file.

The clean-train shift protocol reuses the same model training functions differently. In `benchmark/shift_stage.py`, the code trains a model artifact once on the clean graph for a dataset split and training seed. Then it evaluates that artifact on every selected graph variant. For baselines, the artifact is a state dict plus threshold and hparams. For PMP and SEC-GFD, the artifact also stores the configuration or architectural parameters needed to rebuild the model during evaluation.

The thresholding design is shared across models. Each training function chooses a threshold from validation predictions using `best_f1_macro_threshold()`. Evaluation then applies that threshold to test scores. This design matters because F1 depends on a decision threshold, while ROC-AUC and average precision do not. Choosing the threshold on validation data keeps the test set reserved for final evaluation.

When explaining the models, avoid presenting the specialized methods as magical black boxes. The benchmark does not need to rederive each paper, but it should explain why each model is included. MLP tells us what features alone can do. GraphSAGE tells us how a standard message passing model behaves. PMP represents a method designed around partitioned neighbor aggregation for fraud graphs. SEC-GFD represents a spectral heterophily-aware method. The implementation value is that all four are forced through one evaluation harness.
